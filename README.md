# Noteshub

单人自托管的阅读笔记二次处理工作台。当前已完成电子书闭环：**单用户登录 → 书籍管理 → Markdown 导入预览/修正 → 二读自动保存与状态处理 → 整书 Markdown 导出**。Docker、可选 HTTPS 和备份恢复文件已准备；腾讯服务器尚未部署，纸书和 OCR 尚未开发。

## 启动 Web 应用

使用 Linux、Python 3.12，在项目根目录执行。首次安装：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m noteshub.auth
```

最后一条命令交互创建唯一账号，密码不显示、不通过命令行参数传递，至少 12 字符。没有默认账号和密码，不覆盖已有账号。`requirements.txt` 用于仅安装运行依赖；`constraints.txt` 固定本次验证的间接依赖版本。

仅在本机 HTTP 开发时启动：

```bash
NOTESHUB_COOKIE_SECURE=false .venv/bin/python -m uvicorn noteshub.web:create_app --factory --host 127.0.0.1 --port 8000
```

在启动机器的浏览器访问本机 8000 端口。公网部署需要 HTTPS，保持 `NOTESHUB_COOKIE_SECURE=true`（默认），由反向代理转发至应用的本机端口；不要将上述 HTTP 开发配置直接暴露公网。本阶段没有部署到腾讯服务器，也未配置域名或 TLS。

配置读取进程环境变量，`.env.example` 是说明文件，应用不自动加载 `.env`：

| 变量 | 默认值 | 含义 |
|---|---|---|
| `NOTESHUB_DATA_DIR` | `./data` | 账号、SQLite 和原文件所在目录；初始化账号与启动应用必须指向同一目录 |
| `NOTESHUB_COOKIE_SECURE` | `true` | Cookie 仅通过 HTTPS 发送；本机 HTTP 开发可设为 `false` |

默认 `data/` 已被 Git 忽略。账号只保存带盐 scrypt 密码哈希；会话凭据随机生成，数据库仅保存其哈希，12 小时到期。退出立即注销当前会话并清理其临时预览。连续 5 次密码错误触发全账号 60 秒暂停；没有注册或多用户入口。

## Docker 与部署准备

详见 [部署方案](docs/deployment.md)。已确认使用 `notes.rychoz.com`，复用宿主机 Caddy，保留 FreshRSS、RSSHub 和 Redis。当前改用 GitHub 中转源码，服务器从仓库拉取后构建；尚未执行服务器或 DNS 变更。

- `docker-compose.yml` 只启动本应用，将端口绑定到服务器回环地址。应用以非 root 用户运行，只读镜像层，数据存入独立命名卷。
- `docker-compose.https.yml` 是没有现成反向代理时的可选方案；已有 Caddy 时不要直接启动它抢占 80/443。
- Compose 会自动读取 `.env`；这与上面的原生 Python 启动不同。`.env.example` 不含账号密码。首次 Docker 账号创建使用 `docker compose run --rm --no-deps app python -m noteshub.auth`，已有账号不会被覆盖。
- 应用数据备份使用 `bash scripts/backup.sh /私有目录/唯一备份名.tar.gz`；恢复使用新 Compose 项目和空卷，不能覆盖现有卷。备份含私人笔记和密码哈希，应安全保管并保存异机副本。
- 推荐通过 GitHub 仓库传输，服务器配置独立只读部署密钥；具体步骤见部署方案。只有代码已成功推送到远端后，服务器才能拉取。
- 部署包仍可用 `python3 scripts/package_release.py` 生成，排除 `.env`、账号、数据库、Git 和真实样本；已有归档不会覆盖。

部署包以 `docs/deployment.md` 为入口，只包含运行与运维所需文件，不包含开发测试目录和测试依赖。

仅执行已授权的独立应用部署，不启动第二套 Caddy，不升级或停止既有服务。原生 Python 的 `./data` 不会自动变成 Docker 数据卷；若存在旧数据，要单独确认迁移。

## 本阶段使用流程

1. 登录，创建书籍（书名必填、作者选填），或按书名查找已有书籍。
2. 选择 UTF-8 `.md` 文件，最大 2 MiB；上传后不立即生成笔记。
3. 检查预览。异常处显示完整原始内容及行号，可修改“原文”和“一读评述”；每条修改后点击“保存修正”。正常记录也可展开核对和修改。
4. 所有异常修正后，“确认导入”才可用；服务端也会重新检查，不能通过手工请求绕过。
5. 确认后一次性写入全部笔记，同时长期保留**未改写的原始上传字节**。每本书只允许成功导入一次；相同文件或不同文件再次上传都不能增加或覆盖笔记。
6. 单书页面一次处理一条笔记，显示原文、一读评述和二读输入框；按“上一条/下一条”沿导入顺序移动，跳过不改变处理状态。
7. 输入停止约 500 毫秒后自动保存，界面显示“尚未保存 / 保存中 / 已保存 / 保存失败”；可以“立即保存”或“重试保存”。输入不自动标记完成。
8. “完成并继续”将当前二读文字与已完成状态一起保存，再进入下一条；允许二读为空。最后一条完成后停留本条。已完成笔记可继续编辑，或恢复待处理。
9. 点击“导出整书 Markdown”，先保存当前输入，再下载一本书的一个 UTF-8 `.md`；包含全部笔记，待处理数量只提示、不阻止导出。

### 保存与导出的边界

- 二读编辑需要启用 JavaScript；只加载应用自己的小型脚本，无前端框架。禁用 JavaScript 时输入框保持不可编辑，仍可查看和导出服务器上已保存内容。
- 同一页面的保存请求串行发送，保存过程中继续输入会在后续请求保存最新文字。正常切换笔记、返回列表、退出和导出前先等待保存；失败则保留当前输入并停止该操作。
- 网络恢复会尝试重试；失败时也可点击“重试保存”。登录失效时先复制未保存文字，重新登录并刷新本页后再粘贴继续。
- 没有离线草稿存储或自动合并。跨设备采用**最后成功提交覆盖之前内容**；不要同时在多个设备编辑同一条笔记。另一设备的新内容在重新打开/刷新页面后可见。
- 刷新/关闭有未保存修改的页面时尽力触发浏览器提醒，切后台时尽力提交；浏览器或系统强制关闭、断网、手机挂起时不能保证未保存文字恢复。离开前请等“已保存”。
- 每条二读最多 50,000 字符，保存保留输入文字和换行。原文、一读及成功源文件不会被二读保存修改。
- 导出按导入顺序包含所有笔记；不输出 Zotero 定位链接或图片，不因待处理状态删减内容。文件名处理 Windows 非法字符及常见保留名称。
- 评论按纯文本含义输出：Markdown 标记和 HTML 被转义，普通换行转换为 Markdown 硬换行，CRLF 统一为 LF。这会改变文件中的必要转义字符，**不会把用户文字解释成标题、链接或代码**。数据库中的原始文字不受影响；空评论保持空白。
- 导出读取服务器已保存数据的一致快照；页面按钮会先保存当前编辑。直接调用下载地址仅导出服务器已保存内容，不包含其他页面或设备尚未提交的输入。

预览内容临时存于 SQLite，不放进公开静态目录；限定当前登录会话使用，从上传起 1 小时失效，不因修正而延长。取消、退出、成功确认会清理相关预览；重新上传替换当前会话下同书的旧预览。应用每分钟及启动时清理过期内容。编码错误、空文件或无笔记的上传不创建预览。

“失败不长期保留”允许异常文件在等待修正期间作为临时预览存在；没有确认的文件不会进入长期源文件目录。浏览器直接关闭时应用收不到可靠的取消通知，因此由到期清理兜底。清理指应用存储记录删除，不承诺清除外部备份或磁盘取证痕迹。

数据目录结构：

```text
data/
  account.json         # 唯一账号的密码哈希
  noteshub.sqlite3     # 书籍、会话、临时预览、导入记录、笔记
  sources/             # 仅成功导入的源文件，随机文件名
```

所有书籍、预览、确认/修正、二读保存、整书导出和源文件下载均要求登录；写操作校验 CSRF。文件存储路径不使用上传文件名，网页按纯文本转义，不渲染上传 HTML 或 Markdown。启动会清理确认过程意外中断留下的孤立源文件；正常写入失败会回滚笔记/导入记录并清理文件。

目前直接使用 Python 标准库 `sqlite3`，减少 ORM 依赖；数据库记录 schema 版本，后续表结构变化需显式迁移。本阶段复用已有字段，schema 仍为 v1，无需重建或清空现有数据。备份时先停止应用，再完整复制数据目录；恢复也须同时恢复账号、数据库与 `sources/`，不要只复制正在写入的数据库文件。

## 测试与解析工具

Git 不包含用户的真实 Zotero 文件。无私人样本时，通用测试照常运行，依赖真实样本的 7 项测试明确跳过；本地保留原样本时会执行全部 77 项。解析 CLI 和真实样本浏览器检查仅在自行提供 `tests/fixtures/论爱欲.md` 后运行，不要将此文件或 JSON 预览提交到仓库。

```bash
.venv/bin/python -m unittest discover -v
.venv/bin/python -m noteshub.parser tests/fixtures/论爱欲.md
```

可选真实浏览器检查（运行该脚本的 Python 须安装 Playwright，系统须有 Chromium）：

```bash
python3 tests/browser_smoke.py
```

它使用临时数据和随机测试账号启动本机服务，验证真实样本导入、二读保存/失败重试、前后导航、状态和整书下载；结束后清理测试数据并停止服务。不会创建用户默认账号，也不连接腾讯服务器。手机尺寸模拟不等于真实 iPhone Safari 验收。

解析命令遇到异常时退出码为 **2**，正常且可确认时为 **0**。当前真实样本预期返回 2：154 条记录中有 7 条引号不匹配。这是预期的解析诊断，不代表测试失败。

查看完整预览，包括原文、评述、异常原始内容和行号：

```bash
.venv/bin/python -m noteshub.parser tests/fixtures/论爱欲.md --json
```

JSON 包含私人笔记全文，供本地核查使用。命令只读，不生成导入文件或修改输入。真实测试夹具是用户上传文件的原始副本，未自动修正内容。

## 已确认的解析契约

- UTF-8（含可选 BOM）；兼容 LF、CRLF。
- 空行或只有空格/制表符的行分隔段落，普通换行保留在同一段内。
- 段落以中文 `“` 开头时开始新笔记；允许开头有空格/制表符。
- 从首个 `“` 开始进行深度计数，`“` 加一、`”` 减一；首次回到零时原文结束。算法为确定性的字符扫描，无 AI、无递归。
- 仅去除最外层引号，原文内部引号、空格、换行和标点保留。
- 结束引号后全部作为评述，去除紧邻边界的分隔空格/制表符。评述内的引号不再参与匹配。
- 不以 `“` 开头的后续段落追加给最近一条记录的评述，保留段落间隔。若该记录异常，则仅保留原始内容，等待人工划分。
- 每段独立匹配，未闭合时不跨空行寻找结束引号，下一条以 `“` 开头的段落仍独立解析。
- 文件前部仅识别本次样本中的 `# 注释`、紧随其同段的时间戳和 `### 书名`。头部原始内容也保留在预览中；未知前置文本标为异常，不静默忽略。
- 未闭合引号、空原文、没有原文可归属的前置评述均为异常。空文件或仅头部文件不能确认。
- 仅中文弯双引号是结构标记；不承诺英文直引号、任意 Markdown 模板、列表或代码块形式的摘录解析。
- 不解析或生成 Zotero 定位链接，不推断 EPUB/PDF 来源类型。

这不是通用 Markdown 渲染器：按已批准的导出文本约定分段，不解释富文本语义，也不根据内容猜测边界。若引号在字符层面平衡但语义边界并非用户意图，仍需人工核对预览。

## 预览与人工修正接口

```python
from pathlib import Path
from noteshub.parser import parse_markdown, correct_record, confirm_preview

preview = parse_markdown("“缺少结束引号\n\n“另一条缺少结束引号")

# 仅用合成示例演示手动修正，不包含用户真实笔记。
preview = correct_record(
    preview,
    1,
    original_text="人工核对后的原文",
    first_comment="测试评述",
)

# 其余异常尚未修正，仍不能确认。此处不改写源文件、不写数据库。
assert not preview.can_confirm
# confirm_preview(preview)  # 此时抛出 ValueError，防止部分导入。
```

修正保留源文本、SHA-256、原始摘录及原始错误，标记人工修正；不再次解析人工输入的引号。所有异常修正完成后，`confirm_preview` 才返回按顺序排列的全部笔记。

解析器接口本身只返回内存数据。Web 导入将上传及修正保留在服务器，确认时重新解析同一上传并应用已保存修正，通过 SQLite 事务一次性入库；不接受客户端的 `corrected` 或 `can_confirm` 标志。

成功导入才长期保留上传源文件；失败或取消清理临时上传。此处测试夹具是开发用固定样本，不代表应用会长期保留失败上传。

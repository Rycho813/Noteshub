1. 阅读 README、部署/备份运维文档、SQLite 表结构、导入流程、阅读与导出代码及既有测试。系统为 FastAPI + Jinja2 + SQLite，二读编辑使用原生 JavaScript。`notes`、`imports`、`previews` 均引用书籍，书籍外键没有自动级联删除。

## 功能实现

### 书籍删除

- 书籍列表每张卡片增加“删除书籍”，与进入阅读的链接分开。
- 确认页展示书名、当前笔记数量，并明确删除书籍、全部笔记、导入记录、所有会话的临时预览和原始文件，且无法撤销；可取消返回列表。
- 确认后在 `BEGIN IMMEDIATE` 事务中检查书籍，将对应原文件从 `<随机ID>.md` 改名为 `<随机ID>.md.deleting`，再依次删除预览、笔记、导入记录和书籍。
- 事务提交后清理暂存文件，成功返回 303 到书籍列表；列表重新查询数据库，不保留旧数量或书籍卡片。空书、仅有预览的书，以及已删空笔记但保留导入记录的书均可删除。
- 文件名严格限制为现有的 32 位十六进制随机名，拒绝源文件符号链接、非普通文件和非法路径；原文件已缺失时仍允许清理该书籍的数据库记录。

### 单条笔记删除

- 阅读页增加“删除当前笔记”。进入确认页前走现有保存流程；取消后返回同一笔记，已保存的二读内容仍在。
- 确认页展示当前原文，提示原文、一读和二读一起永久删除，其他笔记及原始导入文件保留。
- 事务以书籍 ID 和笔记 ID 双重限定目标，只删除该行，不更新或重写其他笔记，不删除导入记录或原文件。
- 在同一事务内按 `sort_order` 查找下一条；没有下一条时取上一条；均不存在时返回书籍空状态。保留原排序值，页面位置和导出编号按剩余笔记连续显示。
- 列表和阅读页的数量、完成数、待处理数、阅读位置及导出内容随重新查询更新。删空显示“全部笔记已删除”和 `0/0`，不显示“全部笔记已完成”，隐藏阅读编辑器及导出按钮；直接导出返回 409。
- 删空仍保留原文件下载入口，仍维持“同一本书只能成功导入一次”的既有约束。如需重新开始，应新建书籍。旧页面保存已删除笔记返回 404，不会重建笔记。

### 一致性与故障处理

SQLite 事务与文件系统不能共同提交，因而使用可恢复的中间文件状态：

| 中断/失败位置 | 数据库和文件处理 |
| --- | --- |
| 文件改名失败 | 数据库回滚，书籍与笔记保留 |
| 改名后 SQL 或提交失败 | 数据库回滚；根据仍存在的导入记录，将暂存文件恢复原名 |
| 提交前进程中断 | SQLite 恢复事务后，启动清理根据导入记录恢复文件 |
| 提交后进程中断或文件清理失败 | 书籍已删除，暂存文件没有数据库引用；启动或每分钟清理将其移除 |

暂存名仅用于处理中断，不是回收站，不提供撤销或恢复已提交删除的入口。Linux 对目录执行 `fsync` 持久化改名/清理；Windows 缺少 `O_DIRECTORY`，保留逻辑恢复机制，跳过目录 `fsync`。原有导入文件内容仍执行文件 `fsync`。

正常响应成功前已完成文件清理。清理异常返回 503，明确要求核实列表，说明残留文件会重试；永久权限/磁盘故障仍需人工修复。数据库回滚后的文件恢复如果也失败，同样依靠后续恢复重试，不声称此时已经全部完成。

原文件下载在 SQLite 写锁内把最多 2 MiB 的文件读取到内存，再发送响应，避免查到记录后文件被并发删除改名。阅读页多条查询置于同一读事务，避免并发删除造成页面内部快照不一致。

### 4. 应用版本回滚

把 `release_record` 替换为上面实际保存的文件路径；下列命令在独立 Bash 会话运行。先在新版镜像中处理 `.deleting` 中间状态，成功后才切换旧镜像；若失败，先修复磁盘/权限，不直接启动不识别该状态的旧版。

```bash

cd /opt/noteshub
release_record=/var/backups/noteshub/releases/delete-实际时间戳.env
test -z "$(git status --porcelain)"

ROLLBACK_TAG=$(sudo sed -n 's/^ROLLBACK_TAG=//p' "$release_record")
test -n "$OLD_COMMIT"
test -n "$ROLLBACK_TAG"

sudo docker compose -p noteshub run --rm --no-deps -T app python -c 'from noteshub.config import Settings; from noteshub.db import Store; Store(Settings.from_env())'

sudo env NOTESHUB_IMAGE_TAG="$ROLLBACK_TAG" docker compose -p noteshub up -d --no-build --no-deps app
sudo env NOTESHUB_IMAGE_TAG="$ROLLBACK_TAG" docker compose -p noteshub ps
curl --fail --silent --show-error -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/login
```

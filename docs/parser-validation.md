# 阶段 0：解析验证报告

## 实现范围

- `noteshub/parser.py`：段落分块、嵌套中文引号匹配、评述续接、源位置与诊断、人工修正、整批确认门槛。
- 命令行摘要及 JSON 预览，输入文件只读。
- `tests/test_parser.py`：32 项测试，含参数化子情形；不依赖网络或服务。
- `tests/fixtures/论爱欲.md`：原始真实样本，57569 字节，SHA-256 为 `d41a3ac70b1f2d559f08aa51079bc114994a8c8c9530be9bbd86b47b466eb0f4`。

未实现页面、文件上传生命周期、SQLite、登录、Docker、去重或正式入库。人工修正目前通过 Python 接口验证，尚不是可点击的界面。

## 实际验证

在项目根目录运行 `python3 -m unittest discover -v`：**32 项测试全部通过，无跳过**。

覆盖普通与多层嵌套引号（最高 1000 层）、紧贴评述、无评述、评述内引号、多行和跨段评述、LF/CRLF/BOM、原文空白与标点保留、未闭合/空原文/孤立评述、段落隔离、局部修正仍阻止确认、全部修正后完整返回，以及 CLI 预览和退出状态。

真实样本结果：

| 项目 | 数量 |
|---|---:|
| 已知头部块 | 2 |
| 候选笔记记录 | 154 |
| 结构解析通过 | 147 |
| 需手动修正 | 7 |

通过完整源区间覆盖测试：每个非空白源字符都保留于头部或某条记录的 `raw_source`，区间不重叠；源行号与原文件一致。对选定记录人工比对字段，验证原文、评述、多行评论和内部引号；没有将 147 条结构通过宣称为全部经过人工语义验收。

末尾单独的评述段按用户最新规则归入最后一条评述，不丢弃、不创建独立便签。真实样本与私人评述正文不随 Git 发布。

## 真实样本中的异常

这 7 处均为中文引号深度到段落结束仍未回到零。没有自动补引号或猜测切分，也没有修改测试样本。

| 记录编号 | 原始行号 |
|---|---|
| 3 | 10 |
| 4 | 12 |
| 15 | 35 |
| 16 | 37 |
| 32 | 70–71 |
| 42 | 94 |
| 56 | 122 |

CLI 诊断预期退出 2；`confirm_preview` 预期拒绝确认，直到所有异常手动修正。这与测试通过并不矛盾：测试验证的就是异常不会被静默接受。

## 剩余问题与后续验收

1. 真实文件需要用户在未来预览页面修正上述 7 条记录。当前仅验证修正接口及确认门槛，未代用户修正整份文件。
2. 目前只有一份真实导出样本；尚未独立覆盖 EPUB/PDF 两种来源和其他 Zotero 导出变体。取消定位链接后不能仅凭内容推断来源。
3. 字符匹配不能识别所有语义错误，例如原文意外提前闭合、剩余内容碰巧像评述；仍需人工检查预览。以 `“` 开头的评述段也会被当作新记录，这是当前约定的限制。
4. 上传大小/编码提示、临时文件清理、私有文件访问和事务入库属于后续 Web 阶段；本轮无运行中的网络服务，不宣称端到端导入可用。
5. 下一阶段接入两个纯文本修正字段、源内容与位置显示和确认按钮；服务器端复用当前解析器，所有异常修正后再一次性入库。

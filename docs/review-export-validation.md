# 二读保存、处理状态和整书导出阶段报告

## 完成内容

- 单书处理页一次显示一条笔记，桌面左右布局、手机上下布局。
- 二读纯文本编辑、500ms 防抖自动保存、立即保存、保存状态和失败重试。
- 同页面请求串行：保存中继续输入会随后保存最新文字；前后导航、返回列表、退出和导出先等待保存成功。
- 输入不改变处理状态；“完成并继续”原子保存文字和完成状态；允许空二读完成；已完成笔记可修改或恢复待处理。
- 前后导航严格沿导入顺序，跳过不标记完成；最后一条完成后留在本条。
- 全书 UTF-8 Markdown 导出，包含所有状态、全部笔记，按导入顺序排列；待处理数量只提示。
- Windows 文件名过滤，原文、一读、二读按纯文本转义，保留内层中文引号和换行；不添加定位链接或图片。
- 保存和导出受登录保护；写操作校验 CSRF。API 登录失效返回 JSON 401，不会跟随到登录页后误显示保存成功。

复用已有 `second_comment`、`status` 和 `updated_at` 字段，数据库 schema 仍为 v1，无破坏性迁移，不需要清空上一阶段数据。Markdown 解析库仅用于测试导出结果，不增加运行时依赖。

## 运行方法

在项目根目录安装/更新测试依赖：

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
```

已有账号直接启动；没有账号先交互创建一次：

```bash
.venv/bin/python -m noteshub.auth
```

本机 HTTP 开发启动：

```bash
NOTESHUB_COOKIE_SECURE=false .venv/bin/python -m uvicorn noteshub.web:create_app --factory --host 127.0.0.1 --port 8000
```

已有账号不能重复创建或覆盖；账号初始化与启动必须使用同一个数据目录。完整配置见 [README](../README.md)。以上是本机开发配置，不代表已部署腾讯服务器或配置公网 HTTPS。

重点验证：

## 可靠性边界与剩余事项

- 同页有序保存，跨设备最后成功提交覆盖；没有实时同步、冲突合并或离线草稿数据库。
- 自动保存需要 JavaScript；未保存时刷新/关闭会尽力提示，切后台会尽力发送。手机被系统挂起、强制关闭或持续断网时，不能保证未保存输入恢复；离开前等待“已保存”。
- 登录失效先复制文字，再重新登录和刷新页面后粘贴继续。没有自动丢弃或覆盖本地输入。
- 通过页面按钮导出会先保存当前输入；直接访问下载接口仅导出服务器已保存快照。另一个设备尚未提交的内容不会出现在文件中。
- Markdown 为保留纯文本含义会增加必要转义，并将换行统一为 LF，不承诺文件字节与编辑框文本相同；数据库文本和导入源文件保持独立。
- 本次为 Chromium 实际操作与手机尺寸模拟，未宣称真实 Windows/iPhone Safari 或 Obsidian 应用人工验收完成。
- 目前只有一份真实 Zotero 样本，7 个异常仍需用户实际导入时自行判断。其他来源样本待补充。
- 按本阶段范围没有实施纸书、OCR、Docker、服务器部署或公网 HTTPS；备份恢复、真实设备和实际 Obsidian 打开仍需后续验收。

# V2 第 4/5 步：正式归档

本次合并开发与自动化验证（第 1–2/3 小步骤），第 3/3 小步骤为独立测试实例升级与验收。实际腾讯测试数据与生产服务不会由开发环境直接访问或修改。

## 使用规则

草稿原文必填，一读允许留空。点击“完成一读并归档”先串行保存当前原文/一读，成功后带草稿版本提交归档；保存失败时不生成正式笔记。输入法组字、保存回执丢失、另一页面更新的保护继续沿用草稿编辑规则。

正式归档在一个 SQLite 事务内完成：校验归属、版本、非空原文、来源图片完整性、没有正在运行的识别，然后创建一条 `pending` 正式笔记，锁定来源并提升草稿版本。重复提交或丢失响应后重试返回同一笔记，不会增加计数；异常回滚保留原草稿。不同图片同时归档也按同书顺序追加，避免顺序号冲突。

归档后的来源图片、首次及后续 OCR 历史、原文和一读均长期保留。草稿页显示“已归档 · 待二读”和正式笔记链接；来源转为只读，不允许通过旧标签页继续编辑、重新识别或取消删除。归档来源从待处理草稿列表移到“已归档来源”。本步不提供撤销归档或正式笔记删除入口。

书籍页面可找到图片笔记并查看来源记录；正式笔记可复用现有阅读/二读界面，新增二读交互与完整衔接验收留第 5 步。文字 Markdown 导出包含图片笔记的原文、一读及已保存的二读，不嵌入图片或私有 URL；完整备份包含图片与识别历史。

每本书仍只允许一次 Markdown 导入，图片归档可持续追加。支持先 Markdown 后图片、先图片后 Markdown，以及后续继续加图片；已有笔记 ID、状态、二读、源文件和顺序不改写，新增内容追加到末尾。

## schema v4 与数据保护

v4 在事务中重建正式笔记表，保留旧字段值，增加唯一图片来源关联；图片笔记的 `import_id` 为空，Markdown 笔记继续关联原导入记录。数据库约束限制来源类型、每图片至多一条正式笔记及来源书籍一致性。外键阻止删除已归档来源，过期清理也显式排除被正式笔记引用的图片。

启动自动升级 v1/v2/v3 至 v4。真实 v3 合成夹具含原文 137 字符、一读 17 字符、长期保留图片、成功 OCR 历史及既有 Markdown/二读数据，用于验证迁移逐字段保留及文件摘要不变。迁移失败会回滚，不清空或重建用户数据。

维护工具兼容 v1–v4 的备份与恢复。**升级前先停止测试应用并完整备份。v4 数据不能交给旧 v3 程序运行；不能只切回旧镜像来回退。** 有问题时先停止测试应用，保留新卷和升级前备份，使用旧备份恢复到新空卷再检查，不覆盖现有卷。

## 第 3/3 小步骤：独立测试实例升级与验收

目的：把新功能带到独立测试站点，并保留已有的图片、一读、账号和 OCR 历史。本轮不调用 OCR，无需重配密钥或创建新账号。

### A. 取得新版本、构建并在升级前备份

沿用 GitHub 独立分支中转，无需下载聊天构件。服务器 SSH 终端中将以下流程放在同一组执行：

1. 克隆 `codex/noteshub-v2-archive-test-20261102` 到新的 `~/noteshub-v2-archive-source-20261102`；使用之前已有的 GitHub 只读部署密钥。
2. 对照开发者发布的完整 commit ID，确认取得正确版本。
3. 用 `python3 scripts/package_release.py artifacts/archive-test.tar.gz` 生成发布包，解压到新的 `~/noteshub-v2-archive-test-20261102`，运行 `python3 scripts/check_release.py`。
4. 在新发布目录运行下列命令；任一步失败就停止，不执行后续命令：

```bash
sudo bash scripts/ocr_test.sh build
sudo bash scripts/ocr_test.sh backup
sudo bash scripts/ocr_test.sh up
sudo bash scripts/ocr_test.sh check
sudo bash scripts/ocr_test.sh summary
```

新旧发布目录不同，但 helper 固定使用同一个独立项目 `noteshub-v2-ocr-test` 和数据卷 `noteshub-v2-ocr-test_data`，因此保留原测试内容。当前镜像标签仍带新发布清单摘要，不覆盖旧镜像。不得创建新账号、重写密钥或删除数据卷。`main`、正式 `/opt/noteshub` 和正式卷均不改动。

`backup` 要求测试 app 已停止，若仍运行会拒绝；先执行本项目 stop 再重试备份。它用新镜像中的兼容维护命令读取旧 v3 数据，**不实例化应用、不提前迁移、不调用 OCR**。备份输出到私有目录 `/var/backups/noteshub-v2-ocr-test/`，验证归档内各文件 SHA-256 后才发布，打印 `BACKUP=...`。同目录生成 `.sha256`；文件默认 0600，不输出笔记正文或密钥。私密 OCR key 在数据卷之外，不纳入业务备份。

备份失败时不应启动新 app。备份成功后 up 才触发 v4 升级。check 只检查凭证可读和登录页，不调用接口。OCR 默认关闭，输出 `False` 正常，不要执行 enable-ocr。

首次升级后，已有实际测试数据预计为：

```text
schema_version 4
books 1
image_drafts 1
notes 0
ocr_runs 1
OCR states: [('succeeded', 1)]
Draft lengths/retention: [(137, 17, 1)]
archived_image_notes 0
pending_image_drafts 1
```

如果你之前主动编辑过文字，长度会相应变化；账号、来源图和识别历史应保持不变。把备份路径与 summary 输出保留，不把备份内容或密钥发到聊天。

### B. 浏览器验收（无需再识别）

目的：验证既有数据可以正式归档，并确保新增功能没有额外调用费用。

沿用之前电脑的 SSH 隧道和 `127.0.0.1:18080`，隧道关闭时用自己的服务器登录私钥重新建立。刷新页面，用原测试账号登录。

1. 打开之前那张图片的“识别与一读”，核对原文和一读仍在。
2. 可直接点击“完成一读并归档”；如做修改，按钮会先保存再归档，不需要点击 OCR。
3. 出现“已归档 · 待二读”，原文/一读转为只读，点击“查看已归档笔记”检查书名、正文和一读。
4. 回图片页面，应是待处理草稿 0、已归档来源 1；来源图片及首次 OCR 记录仍可查看。
5. 导出整书 Markdown 核对文字，刷新、退出重新登录后再次核对；不要求本轮填写二读。
6. 再运行 summary，预计正式 notes=1、archived_image_notes=1、pending_image_drafts=0，OCR 仍为一次成功记录；image_drafts=1 是来源保留的正常结果。

重复刷新不会归档第二条，已经归档的按钮会禁用。先不追加新 OCR 调用；同书多次追加、空一读和混合来源已由自动化覆盖，可后续以手动原文图片草稿继续验收。

### C. 停止测试并保留数据

验收后可在**新发布目录**执行：

```bash
sudo bash scripts/ocr_test.sh stop
```

保留同一数据卷、密钥和备份，关闭电脑 SSH 隧道即可。本步不执行 down -v、不清空任何数据卷。后续从新目录 up 可继续访问，OCR 仍默认关闭。不要从旧 v3 目录运行 up，避免旧程序访问已升级数据库。


# Noteshub V2：图片输入与草稿（第 2/5 步）

本文记录第 2 步；第 3 步的识别与编辑保留规则以 [OCR 说明](v2-ocr.md) 为准。

第 2 步只提供书籍下的图片准备和草稿保存；不调用腾讯 OCR，不收费、不生成正式笔记、不修改现有 Markdown 导入规则或二读进度。现有每书一次 Markdown 导入约束仍然有效，图片草稿可以追加。

## 使用

在任一本书页面点击“图片摘录 · 上传与草稿”。手机可拍照或选相册，电脑可选择文件、拖拽到指定区域，或点击该区域后 Ctrl+V / ⌘V 粘贴截图。粘贴监听仅在图片工作区生效，不拦截输入框、评论框和可编辑区域的正常粘贴。

选择图片后，在设备内拖动框选、移动选框或拖动四角改变大小；数字输入可精确调整像素范围。显示缩放只改变查看比例，不降低图片分辨率。“拖动查看放大图”切换到视图滚动模式，返回框选模式后继续裁剪。旋转每次顺时针 90°并重置选区。无需裁剪时使用整张。

“确认范围并预览”仍在设备内处理，没有上传。检查小字清晰度后点“保存图片草稿”。PNG 保持 PNG（无损，保留透明度）；JPEG 以质量参数 0.92 输出；两者保留选区像素尺寸，不为了体积自动缩小。浏览器输出移除 EXIF 等原照片元数据，服务端接收的文件将直接作为后续 OCR 的输入来源。完整原图不会随选区上传；跳过裁剪时会上传整张图经过浏览器重新编码后的版本。

未保存选图仅保留在当前页面，刷新/关闭可能丢失，有未保存提醒；手机系统强制关闭时提醒不保证生效。上传失败时保留当前预览，可重试。同一本书相同内容重复上传返回原草稿，不重复存文件。登录失效时可在另一页重新登录，再返回当前页重试；保存前自动读取新登录令牌，无需刷新丢失选图。

## 保存范围与生命周期

- 图片放在私有数据目录 `images/<随机ID>.png` 或 `.jpg`，不放在静态目录；数据库保存相对路径、校验和、格式、尺寸、字节数及到期时间。
- 需要登录才能查看；所有上传、取消操作检查 CSRF。图片草稿属于书籍、独立于登录会话，重新登录和重启后可继续查看。
- 图片草稿从上传起保留 **7 天**，重复上传/查看不延长。页面显示本设备时区下的到期时间。每分钟及启动/打开图片工作区时清理到期草稿；停机时无法执行清理，恢复运行后执行。
- 主动取消会删除草稿记录和文件；异常中断遗留的未引用文件由清理流程移除。不承诺擦除备份副本或磁盘取证痕迹。
- 第 2 步没有正式图片笔记。“不自动删除正式来源图”的策略留给后续正式笔记功能，本阶段不把临时草稿当作永久笔记。

## 资源限制

| 项目 | 上限 |
| --- | --- |
| 本机输入 | PNG/JPEG，20 MiB、2400 万像素，单边 12000 像素 |
| 最终上传 | 5 MiB、1200 万像素，单边 6000 像素 |
| 服务器处理 | 每应用进程最多同时接收/验证/保存 1 张上传，忙时返回 503，可重试 |

超过限制时要求缩小选区或先缩小图片，不偷偷损失小字质量。HEIC/WebP/PDF/动画等不在本版输入支持范围；不支持时显示转换提示。手机相机提供什么格式由浏览器和系统决定，需真实设备验收。

适合现有 2 核 / 2 GB 单用户服务器。生产继续使用现有单 worker 配置；多 worker 会按进程增加并发上限。后端通过 Pillow 在限定像素后解码校验，不依赖声明的扩展名或 MIME。Markdown 的 2 MiB 限制保持不变。

## 升级、完整备份与迁移

新增固定依赖 `Pillow==13.0.0`，执行 `python -m pip install -r requirements-dev.txt`（生产用 requirements.txt）。应用首次启动自动把 SQLite v1 事务迁移到 v2，仅新增草稿表和索引，不改已有笔记。升级前按原流程停应用并做完整备份。v2 数据库需要 v2 程序，不能直接用旧程序打开；回退应使用升级前备份恢复到新空目录/卷。

完整备份仍使用现有 maintenance CLI / scripts/backup.sh：除账号、SQLite、原 Markdown 文件外，现在还包括所有被草稿记录引用的图片，并检查文件长度、SHA-256 和相对路径。先停应用后备份。恢复要求新空目录，兼容旧 v1 备份；恢复后清除会话和旧 Markdown 预览，图片草稿保留原到期时间、重新登录即可访问。已经到期的草稿在应用启动时清理，不因恢复而续期。

恢复默认解压上限仍为 2 GiB，含图片的备份变大时按实际需要显式传 `--max-bytes`。Markdown 导出仍然是文字导出，不是图片或整应用备份。

**空间管理：** 现有每日备份策略不自动删除旧备份。图片加入后，每份完整备份可能明显变大，需要检查磁盘余量并安排异机副本/人工保留策略。本次不修改生产定时任务，不自动删旧备份。

## 验证与人工验收

后端测试：`.venv/bin/python -m unittest discover -v`。

可选真实 Chromium 自动化：`python3 tests/browser_images.py`，需要执行该脚本的 Python 有 Playwright、Pillow、httpx，系统有 Chromium。脚本使用随机临时账号和合成图片，启动本机临时服务并在结束后停止，测试数据自动清理，不访问腾讯服务。截图保存到 Git 忽略的 `test-results/`。

人工验收：

1. Windows 浏览器选图、拖入截图、截图后 Ctrl+V；Mac 上截图后 ⌘V。
2. iPhone/Android 实际拍照、相册选图；确认照片方向、HEIC 不支持时的提示。
3. 手机上框选、拖动四角、旋转、缩放和切换查看模式；不出现横向页面溢出。
4. 放大检查中文小字的清晰度，确认选区外内容未上传。
5. 刷新、退出重新登录后查看草稿；取消后不能再访问图片。
6. 原有二读评论中的文字粘贴与保存正常；Markdown 导入与导出正常。

自动化移动尺寸/触摸模拟不等于真实 iPhone Safari 或相机验收。本阶段未部署到腾讯生产服务器。

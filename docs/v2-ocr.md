# Noteshub V2：腾讯 OCR 与一读草稿（第 3/5 步）

本阶段连接第 2 步图片上传/裁剪，增加按需识别、原图核对、原文编辑和一读笔记自动保存。**仍不生成正式笔记、不接入二读、不把草稿放进整书 Markdown 导出。** 第 4/5 步再处理正式归档，第 5/5 步处理二读衔接。

开发验证使用合成图片、模拟 OCR 和模拟 HTTP 传输，没有真实上传腾讯、没有识别费用，也没有部署生产服务器。真实图片效果、账户权限、额度、区域和网络需要配置后另行验证。

## 使用与数据保留

1. 在书籍的“图片摘录”页面上传并确认裁剪范围，保存图片。
2. 点击该图片的“识别与一读”。编辑器准备完成后，图片/草稿退出 7 天清理规则，长期保留直到主动删除。未进入编辑/识别的图片仍按上传起 7 天清理。
3. 点击“识别文字”才提交腾讯，使用 `GeneralAccurateOCR`，图片通过后端 Base64 上传，不提供公开图片 URL。默认关闭；配置缺失时不建立识别任务，可先手动填写。
4. 识别成功后对照图片校对原文、写一读。输入停止约 500 毫秒自动保存，也可“立即保存”；中文输入法组字期间不提交半成品。刷新/关闭前确认“已保存”。没有离线草稿存储，系统强制关闭/断网不保证未保存内容恢复。
5. 首次成功结果单独保留，包括提供方行顺序、文字、置信度/位置（若返回）和请求 ID；不润色、不补字、不转成 Zotero Markdown 再解析。只在原文从未保存编辑过时把首次成功文字填入原文。曾经编辑过时可明确“采用”候选结果，一读评论不受影响。
6. 再次识别必须明确点击并确认可能再次计费。它只增加结果历史，不覆盖原文/一读或首次成功结果；“采用这份结果作为原文”是另一项明确操作。

识别与保存状态分开显示。识别进行中刷新、离开后回来都只查询已有任务，不重新调用服务。第一次识别且没有任何编辑时暂时锁定文本框，避免自动填入与输入竞争；已有编辑内容时允许继续保存，后端版本检查防止覆盖。

保存请求在同页串行处理。丢失保存回执时先对照服务器确认上一份快照，再提交后续输入；其他页面/设备已改动时返回冲突，保留本地输入，需复制后刷新核对，不做静默合并。登录失效时可在另一页登录再回本页重试，无需刷新丢掉输入。

主动删除编辑草稿前会提示；删除后 OCR 历史、校对/一读和来源图一起清理，备份副本不会因此抹除。识别中的草稿不能删除。

## 费用、任务和失败处理

- 单次点击创建一个持久化任务，使用前一任务 ID 防重复提交；SQLite 唯一索引限制整份数据同时只有一项识别在运行，即使多个应用实例也不能同时认领第二项。
- 使用官方模块化 SDK，固定 OCR 包 `3.1.193`、common 包 `3.1.199`。显式 `NoopRetryer`、禁用区域切换重试，单次 HTTP 超时参数 30 秒，保持 HTTPS、证书校验与继承的代理/CA。
- 后端图片最大 5 MiB，Base64 约 6.7 MiB，在所安装 SDK 文档注明的 10M Base64 上限以内；沿用第 2 步像素限制。只支持本工具已校验的 PNG/JPEG，不额外开放 URL/PDF 等输入。
- 网络超时、进程中断或结果落盘失败不能证明腾讯没执行/没收费。120 秒未确认结束的任务标为“未能确认完成”，不自动重试，迟到的旧任务结果不能改写后续状态。
- 正常关闭应用会等待已启动任务保存结果。恢复备份时，运行中任务直接标为中断，不自动再次识别。手动重试可能再次计费；控制台费用/请求记录才是实际结算依据。
- SDK 错误只保存固定分类，不保存异常全文；页面和日志不显示签名头、密钥或图片 Base64。SDK 请求/响应 debug 日志被关闭。

## 安全配置凭证（无需把密钥发给开发者）

先在腾讯云开通文字识别，并通过 CAM 创建 Noteshub 专用 API 子用户，只赋予所需 `GeneralAccurateOCR` 权限，避免主账号密钥。在安全编辑器中填写下面两个字段到**仓库和应用数据目录以外**的私密 JSON 文件：

```json
{
  "SecretId": "在安全编辑器中填写实际 SecretId",
  "SecretKey": "在安全编辑器中填写实际 SecretKey"
}
```

临时凭证可另外提供 `Token`。不要把值发到聊天、提交 Git、写进命令行参数、截图或日志。文件必须是普通文件、小于 16 KiB，只允许所属用户读取（例如 0600/0400）。应用读取配置时检查这些权限；不把凭证写入 SQLite 或业务备份。

腾讯 SDK 在本机使用真实 SecretKey 计算 HMAC 签名，**只在代理转发时替换的占位密钥不能用于本机签名**。运行环境需要能够安全提供真实私密文件或真实进程变量；不支持时继续用模拟测试，不能把占位值当作已验证的腾讯凭证。

### 原生 Python

建议私密文件如 `/私密目录/tencent-ocr.json`，所属用户为运行应用的用户，文件 0600、父目录仅该用户可访问。设置非秘密的进程配置：

```bash
export NOTESHUB_OCR_ENABLED=true
export NOTESHUB_TENCENT_CREDENTIALS_FILE=/私密目录/tencent-ocr.json
export NOTESHUB_TENCENT_REGION=ap-guangzhou
```

然后按原生应用的启动方式运行。应用不自动读取 `.env`。也支持通过可信运行环境注入 `NOTESHUB_TENCENT_SECRET_ID`、`NOTESHUB_TENCENT_SECRET_KEY`、可选 `NOTESHUB_TENCENT_TOKEN`，不要在命令行写值；配置了文件时优先使用文件，不悄悄回退到另一份密钥。

下面只检查**本地配置可读**，不调用腾讯，也不证明账户权限或网络可用：

```bash
.venv/bin/python -c "from noteshub.ocr import TencentOCR; TencentOCR().prepare(); print('OCR 本地配置可读，尚未调用接口')"
```

### Docker Compose（可选，不会自动启用）

基础 `docker-compose.yml` 不传密钥，默认 OCR 关闭。新增可选 `docker-compose.ocr.yml` 通过 Compose secret 只读挂载私密文件。

- 主机私密文件可放 `/etc/noteshub/tencent-ocr.json`，内容由你用安全编辑器填写，不放在 checkout、镜像或数据卷。
- 当前应用容器 UID/GID 是 10001。挂载文件应由 UID 10001 可读，例如属主 `10001:10001`、模式 `0400`；实际文件挂载不会自动替你修改宿主机权限。主机父目录保持私有。
- 在未跟踪的 Compose `.env` 中只写非秘密配置：`NOTESHUB_OCR_ENABLED=true`、`NOTESHUB_TENCENT_CREDENTIALS_PATH=/etc/noteshub/tencent-ocr.json`、可选区域配置。
- 未来启动**独立测试实例**时显式合并两个 Compose 文件，并指定独立项目、镜像标签和回环端口；不要直接替换正式实例。本次没有执行任何容器部署操作。
- 现有 backup/restore 脚本可以继续使用基础 Compose 文件：维护命令不需要 OCR 密钥；完整备份不会包含单独挂载的密钥文件。

不要通过 `env`、`docker compose config` 的完整输出或容器 inspect 环境内容来排查密钥。只检查变量名称/是否配置、文件权限与安全错误分类。改完进程变量需重启独立测试应用，重新打开页面。

## 网络与一次真实验证

需要允许服务端 HTTPS 访问 **`ocr.tencentcloudapi.com:443`**。保留环境提供的代理和 CA，不关闭 TLS 校验，不绕过网络策略。

本次检查：当前托管云环境没有腾讯凭证绑定或相关进程变量，网络白名单也不包含该主机；没有修改白名单或伪造凭证。若在此环境做真实验证，需要先通过环境设置添加该域名，并使用支持本地签名的安全凭证注入方式。若在腾讯服务器上验证，则配置独立测试应用所用的网络和私密文件。

配置就绪后：

1. 在独立测试应用选择一本测试书，用一张无敏感内容的中文书页拍照/截图并裁剪上传。
2. 进入编辑，点击一次“识别文字”，等待成功；失败时先查看安全错误提示和腾讯控制台，避免反复点击。
3. 对照原图改一处文字并写一读，确认“已保存”，刷新并重新登录后检查。
4. 检查腾讯控制台对应请求及用量。一次真实调用只验证该图片和当前配置，不能替代多样图片的准确率评估。

## 数据升级、迁移和验证

启动时由 schema v1/v2 事务升级至 **v3**，保留已有图片、笔记及导出数据。新增编辑字段和 OCR 历史表，未改变正式笔记表。升级前停应用并完整备份；v3 不能交给旧 v1/v2 程序直接运行，回退应恢复升级前备份到新空目录。

完整备份包含来源图片、首次及后续识别结果、校对原文、一读内容和编辑保留标记。兼容 v1/v2 备份恢复后升级；恢复到新目录后重新登录即可继续编辑。恢复默认 2 GiB 上限、同机每日完整备份累积占用和异机副本要求仍按 [备份说明](backup-operations.md) 与 [图片说明](v2-image-drafts.md) 执行。

测试命令：

```bash
.venv/bin/python -m unittest discover -v
python3 tests/browser_images.py
python3 tests/browser_ocr.py
```

两个浏览器脚本需要执行它的 Python 有 Playwright、Pillow、httpx，系统有 Chromium；应用服务使用项目 `.venv`。OCR 浏览器脚本启动 `tests/ocr_fixture_app.py`，仅在测试模块注入模拟提供方，无生产“假识别”开关，部署归档不包含 tests。SDK 单元测试使用真实 SDK 签名/序列化路径，仅拦截 HTTP 传输，所有凭证均为测试假值。

模拟测试覆盖交互和错误处理，不证明腾讯账户、真实识别质量或实际费用。真实手机相机、Mac 剪贴板和 iPhone Safari 仍需用户后续验收。
